Put your HYROX Tracker on Firebase

After these steps you'll have your own free web address. Anyone you send it to signs in with Google and gets their own profile.

About 20 minutes₹0, no card neededNeeds a computer once

What's in this folder

public/The tracker itself: plan, logging, charts, timers. You don't need to open anything in here. firestore.rulesThe database rules: anyone who signs in with Google can see the tracker, people can only change their own logs and your account is the admin. Leave it as it is. redirect/A one-page site that forwards the old address to hyroxtraining.web.app. Leave it as it is. storage.rulesWho can add and delete photos (same as logs: your own and the admin can do anyone's). Leave it as it is. firebase.jsonTells Firebase what to publish. Leave it as it is.
1

Create a Firebase project

  1. Open console.firebase.google.com and sign in with your Google account.
  2. Click Create a project (or Get started) and give it a name, for example vinay-hyrox.
  3. Under the name you'll see a project ID. It becomes your web address: project-id.web.app. Click the pencil next to it if you want a different one.
  4. Turn Google Analytics off (the tracker doesn't use it), then click Create project.

Type your project ID here and the commands in step 6 will fill it in for you:

You stay on the free Spark plan. If Firebase ever suggests upgrading to Blaze, you can ignore it; nothing here needs it.
2

Turn on "Sign in with Google"

  1. In the left menu, open Build → Authentication → Get started.
  2. On the Sign-in method tab, click Google, switch it to Enable, pick your email as the support email and click Save.
3

Create the database

  1. Open Build → Firestore Database → Create database.
  2. If it asks for an edition, choose Standard.
  3. Location: choose asia-south1 (Mumbai). It's closest to you and it can't be changed later.
  4. Choose Start in production mode and click Create. The tracker's own rules replace the default ones in step 6.
4

Register the web app

  1. Go back to Project Overview (the house icon at the top left), click + Add app and choose the </> (Web) icon.
  2. Nickname: HYROX Tracker. Tick Also set up Firebase Hosting for this app, then click Register app.
  3. Click Next through the remaining screens and then Continue to console. You don't need to copy anything: the tracker picks up these settings automatically once it's published.
5

Install Node.js (one time)

Firebase publishes websites with a small command-line tool that runs on Node.js.

  1. Go to nodejs.org, download the LTS version and install it, keeping all the default options.
6

Publish the tracker

Open a command window in this folder (the folder that contains firebase.json):

  • Windows: open the folder in File Explorer, click the address bar at the top, type cmd and press Enter.
  • Mac: open the Terminal app, type cd (with a space after it), drag this folder into the Terminal window and press Enter.

Log in to Firebase. Paste this command and press Enter. If it asks Ok to proceed? type y. A browser window opens: sign in with the same Google account and click Allow.

npx firebase-tools login

Publish. This uploads the tracker and your access rules together:

npx firebase-tools deploy --project YOUR-PROJECT-ID
When it finishes you'll see Hosting URL: https://your-project-id.web.app. That's your tracker's address.
Can't remember the project ID? In the Firebase console, click the gear icon next to Project Overview → Project settings.
Updating to v32? Use this same command (not "hosting only"): v32 also changes the access rules, so that members can add exercises and change sets in the shared plan and so that body check-ins and your own exercises can be saved. Until the new rules are published, those saves are refused.
7

Sign in and set up your profile

  1. Open https://your-project-id.web.app and click Sign in with Google.
  2. The first time, it asks you to set up your profile: your name, colour, your race (Singles, Doubles or Relay and your division) and race plan. Click Start tracking.
  3. That's it. From now on, signing in with the same Google account on any phone or PC opens your own log straight away.
The admin is admin@example.com, an account that doesn't train, so it has no log of its own. Signed in with it, you'll see an Admin badge at the top. Tap the name there to pick whose log to open and change, or to edit the plan.
8

Put it on both phones

  1. Send your training partner (or anyone else training with you) the link. They sign in with their Google account and set up their profile once.
  2. iPhone: open the link in Safari → Share button → Add to Home Screen. Open the new icon and sign in once more (home-screen apps on iPhone keep their own sign-in).
  3. Android: open the link in Chrome → ⋮ menu → Add to Home screen or Install app.
Everyone who signs in can see everyone's logs (that's how Together and Progress compare you). Each person can only change their own. Only you, as admin, can change other people's logs, remove members or edit the plan.
The tracker now opens even with no signal at the gym. Anything you log waits on the phone and syncs when you're back online.

Your address: hyroxtraining.web.app

The tracker is published at https://hyroxtraining.web.app. The original https://your-project-id.web.app can't be deleted, so it now forwards every visit to the new address.

  1. In the Firebase console open Hosting & Serverless → Hosting, scroll down to Add another site, type hyroxtraining and add it. If Firebase says the name is taken, pick another and put it in place of hyroxtraining in firebase.json, public/index.html and redirect/.
  2. Open Authentication → Settings → Authorized domains. If hyroxtraining.web.app isn't listed, click Add domain and add it. Without this, Google sign-in on the new address is refused.
  3. Publish as usual. The command updates both addresses at once.
  4. Open https://hyroxtraining.web.app, sign in once and add it to your home screen again (then remove the old icon).
Your logs, profiles and photos don't move: it's the same database, just a new address.

Photos at full quality (optional)

Photo storage needs Firebase's pay-as-you-go Blaze plan. At your usage it should stay within the free allowance (5 GB stored, 100 GB of downloads a month), so ₹0, but Google asks for a card and there's no automatic spending cap, so you set an alert.

  1. Upgrade: in the Firebase console, click Upgrade at the bottom left (next to "Spark"), choose Blaze and create a billing account with your card. Google may verify the card with an OTP or a small temporary charge.
  2. Set a budget alert: when the upgrade offers a budget, enter ₹100. If you skipped it: console.cloud.google.com/billing → your billing account → Budgets & alerts → Create budget → ₹100, alerts at 50%, 90% and 100%. You'll get an email if costs ever start.
  3. Create photo storage: in the left menu, open Databases & Storage → Storage → Get started. For location pick US-CENTRAL1 (it's marked no-cost; Mumbai has no free allowance). Choose Start in production mode and click Create.
  4. Publish again with the usual command, which now also uploads the photo rules:
npx firebase-tools deploy --project YOUR-PROJECT-ID
Then on any session, scroll to Finish session → Add photo. The original is kept at full quality; the app also saves a small preview so browsing stays fast. Tap a photo to see it full size.
Haven't set up photo storage yet but want to publish other updates? Use npx firebase-tools deploy --only hosting,firestore --project YOUR-PROJECT-ID. The normal command stops with an error until Storage exists.

Later on

Adding someone else

The tracker is private. Ask them to open the link and sign in once (they'll see "This tracker is private"). Then in Firebase console → Authentication → Users, copy their User UID and add it to members() in both firestore.rules and storage.rules. Run the publish command from step 6 again; next time they sign in they set up their profile. One Google account is one profile.

Making someone else an admin

Add their User UID (Firebase console → Authentication → Users) to admins() in firestore.rules and storage.rules as well as TRACKER_ADMINS in public/config.js. Then run the publish command from step 6 again.

Getting an updated version of the tracker

Replace the files in the public folder with the new ones and run the publish command from step 6 again. Your logs live in the database, so they aren't touched.

Keeping your own copy of the data

Every few weeks, go to Settings → Full backup (JSON). On a phone this opens the share sheet, where you can choose Save to Files or send it to yourself.

If something goes wrong

The publish command says the database doesn't exist

Step 3 wasn't finished. Create the Firestore database, then run the publish command again.

"Failed to get Firebase project" or "project not found"

The project ID in the command doesn't match. Copy it exactly from Project settings, which shows it in lower case with dashes.

"'npx' is not recognized" (Windows) or "command not found" (Mac)

Node.js isn't installed yet, or the command window was already open while it installed. Finish step 5, close the command window and open a new one.

The tracker says "…can't open this tracker yet" after signing in

The database rules weren't published, so Firebase is still using its locked default rules. Run the publish command from step 6 again and check that it finishes without errors, then sign in again.

Sign-in says Google sign-in isn't switched on

Repeat step 2 and make sure you clicked Save.

Nothing happens when tapping "Sign in with Google"

The link was probably opened inside another app, such as Instagram. Open it in Chrome or Safari instead. On iPhone, if the home-screen icon doesn't finish signing in, use the tracker in Safari.

Firebase's free Spark plan includes 1 GiB of database storage and 50,000 reads a day, far more than a small group logging workouts will use.
